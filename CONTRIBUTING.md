# Contributing

Thanks for helping. For a small fix, open a pull request. For anything bigger, open an issue first so we can agree on the approach.

## Setup

You need [uv](https://docs.astral.sh/uv/), Node 20 or later (for the release script tests), and Sublime Text 4 to try changes live.

```bash
git clone https://github.com/MMSs/sublime-csv-table.git
cd sublime-csv-table
uv sync
uv run pytest
```

CI runs `uv run pytest` and `node --test scripts/release/bump.test.mjs` on macOS, Linux and Windows with Python 3.8 and 3.13.

## Run your checkout in Sublime

Link the checkout into your `Packages` folder (**Preferences → Browse Packages…**) under the name `CSV Table`:

```bash
# macOS
ln -s "$PWD" "$HOME/Library/Application Support/Sublime Text/Packages/CSV Table"
# Linux
ln -s "$PWD" "$HOME/.config/sublime-text/Packages/CSV Table"
```

```bat
:: Windows, elevated prompt
mklink /D "%APPDATA%\Sublime Text\Packages\CSV Table" "C:\path\to\sublime-csv-table"
```

Sublime reloads `csv_table.py` on save but keeps the old `csv_format` module loaded. Restart Sublime after changing `csv_format.py`.

## Commands

| What | Command |
|---|---|
| All tests | `uv run pytest` |
| One file | `uv run pytest tests/test_csv_format.py` |
| One test | `uv run pytest -k <name>` |
| Release script tests | `node --test scripts/release/bump.test.mjs` |
| Rebuild the syntaxes | `uv run python scripts/build_syntaxes.py` |

## How the code is organised

- `csv_format.py`: parsing and formatting. Pure Python, no `sublime` import, so it is tested under plain Python.
- `csv_table.py`: the Sublime command, the delimiter panel and the highlighting.
- `CSV*.sublime-syntax`: generated by `scripts/build_syntaxes.py`. Do not edit them by hand; a test fails if they are stale.
- `docs/design.md`: the formatting rules in detail.

Rules:

- No third-party runtime packages. The plugin must run on Sublime's bundled Python 3.8.
- Keep `csv_format.py` free of `sublime` imports and import-time side effects.
- Update `README.md` when behaviour or settings change.

## Pull requests

`main` is protected. Every change goes through a pull request, which is squash-merged once CI and the PR title check pass. The PR title becomes the commit message, the changelog line and the version bump, so it must be a [Conventional Commit](https://www.conventionalcommits.org/):

| PR title | Release |
|---|---|
| `fix:` / `perf:` | patch |
| `feat:` | minor |
| `feat!:` or `BREAKING CHANGE:` in the body | major (minor before 1.0) |
| `docs:` `refactor:` `test:` `ci:` `chore:` | none |

Do not edit the version in `pyproject.toml` or `CHANGELOG.md`. The release workflow does that.
